# 研证：两份真实公开案例

这是基于两篇真实公开论文制作的实际工作台案例，包含公开正文、真实千问调用和本次对话中的作者决定。不是外部用户试用报告，也没有宣称新科研成果或完成正式实验。

## 阅读与回放

- `研证-两份真实公开案例-三分钟.mp4`：180秒、1920×1080、中文字幕版，无配音。回放已保存的真实调用与代录结果，调用等待时间未在录屏内重放。实际选择、拒绝动作及时间另存于 `video/operation-history.json`；最终成片无需再次改变决定。
- `index.html`：离线打开的案例总览与文件索引。
- 在原项目输出目录双击 `查看真实案例.cmd`：启动独立案例数据库的本机工作台。不会更换主工作台数据库，也没有发布或修改魔搭入口。该服务不因启动而调用模型。
- `A/EXECUTION-PLAN.md`：完整一周计划、可运行命令、基线、指标和停止标准。
- `B/NARROWING-DECISION.md`：停止原推断、收窄目标的证据与理由。
- `研证-真实案例与演示.zip`：可离线审阅的完整证据包，解压后打开 `index.html`；`MANIFEST.json` 列出逐文件指纹。

压缩包附有同一实验脚本 `A/run_experiment.py`。安装 Python 与 NumPy 后，可在解压目录运行 `python A/run_experiment.py --suite smoke --output new-smoke`；正式90组用 `--suite full` 并使用新的输出目录。该命令不调用模型。案例实际冒烟环境为 Python 3.12.14、NumPy 2.5.4。

## 三种记录分别保留

成片顺序：0:00 总览；0:12 案例A；0:36 点击引用回原文；1:02 取舍与计划；1:31 案例B；1:43 原文与收窄；2:10 拒绝轨迹；2:23 调用记录；2:35 人工确认与交付索引。

1. **原文**：`sources/` 保存固定版本PDF和实际获取记录；`A/project.json`、`B/project.json` 保存页码、字符位置、原句、文件/页文本哈希。相关正文核对不代表通读。
2. **模型**：`model-audit/` 为9次真实请求的消息、返回内容及程序调用事实；`model-calls.json` 为清单。实际 Request ID、时间、Token、失败、拒绝、截断均保留。API成功与结构校验通过、科研内容正确是不同状态。没有使用假模型替代结果。
3. **人工**：`human-confirmation.json` 保存作者在本对话中的原答复、授权边界和审阅文件指纹。网页由Codex依授权代录，模型拒绝意见中的科学细化属于制作助手审阅，不伪称作者逐项独立完成。`proposal-reviews.json` 保存草案轨迹。

## 当前结局

A已代录选择误差—代价对照方向，正式90组实验尚未执行。脚本只运行了6组小规模冒烟检查，见 `smoke/`；不能用来宣称普遍加速。

B已按作者决定停止“仅凭谱范数残差验收PCA”的原目标，收窄为补充分量方差等指标。错误的替代模型草案被拒绝，尚未选择新的模型课题。初始本地模板与被拒草案仅作为过程历史保留，收窄后的人工协议以 `B/NARROWING-DECISION.md` 为准。

3×3辅助诊断受原文讨论启发；它没有复现原文图1的数据实验，也不证明具体随机SVD算法必然产生某个坏输出。

## 验证

`validation.json` 核对两份论文文件指纹、精确摘录绑定和来源记录结构；`video-validation.json` 核对视频时长、编码、文件指纹与抽帧。结构/字节一致不等于科学结论得到认证。

代码回归：方向流程12项、待确认草案6项、全部前端113项通过，日志见 `verification/`。实际Chrome录制检查引用位置与当前案例一致，B拒绝理由通过API回读核对；来源摘录按检索记录隔离，避免同名S001串绑。

`workbench-backup.json` 可通过现有备份入口恢复两份项目文字记录；JSON备份不带原始PDF字节，可按来源重新上传 `sources/` 中同一PDF。`cases.db` 是包含原PDF的独立数据库，留在原项目目录用于工作台回放；证据包中的 `case-database.snapshot.db` 是它的完整一致性快照，包含两份项目及原PDF。压缩包供独立审阅，运行完整工作台仍需原项目环境。
