# 研证：本地产品试用交付

日期：2026-10-23。面向学生研究入门、导师与课题组讨论。本轮在已有科研流程上改善可用性、数据留存与失败处理；保留本地单人工作台定位，应用版本仍为 0.5.0。

## 这轮改善了什么

| 原问题 | 现在的行为 |
|---|---|
| 页面有多个相似入口，开始后不知道下一步 | 首页说明交付物；当前研究只突出一个下一步，五步卡片显示实际进度；可选检索与指纹字段按需展开 |
| 项目多后难以找到上次的研究 | 按标题、想法、已选方向搜索，按阶段筛选；输入时保留焦点，可一键清除筛选 |
| 只有单项目导出，换机和误操作缺少保障 | 从研究项目页下载版本化工作空间备份；恢复只新增缺失项目，同 ID 跳过，不覆盖现有记录 |
| 旧备份中的“成功”容易被误认成本机刚执行 | 恢复研究、工具与核查记录携带导入来源；Markdown、独立记录和实验 CSV 导出保留说明；原行动计划暂停，旧待审提议须重新生成 |
| 更新源码后可能仍打开旧进程 | 启动器比较进程启动时的源码指纹；发现旧服务后提示在原窗口停止并重新启动；端口被其他程序占用时给出提示 |
| 失败后不清楚如何继续 | 启动状态与项目打开失败可重试；备份格式、完整性、版本、大小和归属错误给出中文说明，拒绝部分写入 |

## 开始使用

保留完整仓库与现有 Python 环境，从项目根目录运行：

```powershell
.\webapp\Check-Workbench.ps1
.\webapp\Start-Workbench.ps1
```

检查器只读依赖、公开运行文件与本机状态接口，不打开研究库、不调用模型。缺少环境时先运行 `webapp/Setup-Workbench.ps1`。如提示旧版本，请在原启动终端按 Ctrl+C 后重新运行启动器。自定义端口可为两条命令添加 `-Port 端口号`。

正常使用流程：写下问题并创建研究 → 导入导师给的 DOI/arXiv 题录 → 核对原文并确认实际阅读 → 比较候选、填写选择理由 → 带走研究决策包。模型修订仍先预览、再由研究者接受。创建行动计划不执行工具，点击具体行动才执行。

## 备份与恢复

在“研究项目 → 备份与恢复”点击“下载工作空间备份”，妥善保存 JSON。换到另一份本地工作台后，点击“选择 JSON 备份并恢复”，选择该文件；选择后会立即校验并恢复，界面报告新增和跳过数量。单个项目 JSON 不属于工作空间备份格式。

当前格式为 `yanzheng-local-backup` v1，单份最多 20 MiB、1000 个研究。导出使用一致性数据库快照；恢复先完整校验，再在一个写事务中新增。文件损坏、重复 JSON 字段、项目重复 ID、错误归属或写入失败均不会留下半份恢复结果。内容 SHA256 检查完整性，不证明文件来源可信。

备份包含研究文本、历史题录、阅读声明、提议及结果记录；不含应用配置中的模型密钥、原件附件或机器配置。研究者自行写入笔记的敏感内容仍属于研究文本，应妥善保管文件。恢复保留历史内容和标识，但不重新访问论文、执行实验、调用模型或核验数学结论；新机器上的原件可用性需要另行检查。

恢复后的行动计划暂停，在途行动记为结果未知；待审提议保留历史，但旧上下文不能直接接受。重复导入同一份备份跳过已有 ID，不用于回滚或覆盖更新后的研究。

## 架构取舍

沿用同源 FastAPI、SQLite 事务、已有模型适配器与无构建前端。备份合同放在现有 `storage.py`，保留现有运行包模块清单；没有增加数据库、消息队列或新的智能体框架。恢复请求在 20 MiB 边界内读取，校验与写入在线程池执行；请求结果不会自动触发研究工具。

`/api/status` 返回在应用创建时固定的公开源码指纹。指纹覆盖后端 Python 与静态界面文件，不覆盖 `.env`、研究库或用户材料。它用于提示旧进程，不是发布签名或安全认证。

持续检查增加前端行为测试与环境完整性检查，运行环境改为 Windows，以匹配现有 Windows 原件访问实现。Action 用法参考官方 [setup-node](https://github.com/actions/setup-node)、[setup-python](https://github.com/actions/setup-python) 与 [checkout](https://github.com/actions/checkout)。本轮未触发远程 CI。

## 本机验收

- Python 全量：369 项，零失败、零错误；其中 4 项因 Windows 创建符号链接权限不足跳过。日志：`tmp/product-polish-python.log`。
- 前端：103 项行为测试通过，JavaScript 语法检查通过。
- 科研闭环真实 Chrome：12 项检查通过，使用隔离库、合成题录与模型替身；包含实际导出下载。记录：`output/research-journey-acceptance/1792756114994-6d39e4/validation.json`。
- 产品真实 Chrome：15 项检查通过，跨两份隔离数据库验证实际下载/恢复、重复导入不覆盖、无效与重复字段 JSON、项目搜索、刷新、320/390px 布局，以及启动检查。1440×1050 下主创建按钮底部约 971px，完整位于首屏。最终记录与截图见下方交付索引。
- 原件访问：修复与实际负载不一致的核验结果可被当成已验证的问题；不一致时拒绝预览。此前集成测试的 Windows 临时目录祖先访问限制，通过把真实测试夹具放到仓库隔离目录解决，未放宽生产访问校验。
- 备份最终独立复核：后端 19 项、前端恢复 3 项通过；覆盖独立导出来源、原文 JSON 提交、理论归属与点路径 ID。
- 启动器实际 PowerShell 检查：用自有临时端口模拟旧进程和其他程序占用，两种情形均给出正确提示并退出，没有创建数据库；当前版本的识别由产品浏览器验收覆盖。

上述离线模型替身验证产品流程，不代表真实模型输出质量、论文内容或数学结论通过审查。正式研究库与原有运行服务未操作；魔搭入口与部署目录的 20 份原有文件逐项哈希一致。仅进行了本地打包兼容性检查，没有上传、发布或运行容器。

复现入口：

```powershell
webapp/.venv/Scripts/python.exe -X utf8 -B scripts/run_tests.py --suite all
node --test webapp/tests/frontend/*.cjs
node scripts/research_journey_browser_acceptance.cjs
node scripts/product_browser_acceptance.cjs
```

浏览器脚本需要 Playwright 与本机 Chrome，可用 `PLAYWRIGHT_MODULE` 指定已安装的 Playwright 模块、`YANZHENG_QA_BROWSER` 指定已安装的浏览器通道。脚本自行创建并清理所启动的临时服务，数据和截图保存在独立 `output/` 子目录。
