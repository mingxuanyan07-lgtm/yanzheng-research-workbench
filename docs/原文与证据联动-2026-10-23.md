# 原文与证据联动交付

本轮把“题录 → 原文 → 摘录 → 已确认笔记 → 候选判断 → 原文定位”接入现有工作台。魔搭演示入口保持不变。验收使用独立临时数据库、合成题录与合成模型，不操作正式研究库或既有运行服务。

## 使用方式

1. 在文献工作台检索论文，或用 DOI / arXiv 编号导入题录。
2. 展开题录下的“上传原文，在工作台阅读与摘录”，选择文件并确认它对应当前题录。上传支持有文字层的 PDF，以及 UTF-8 TXT / Markdown。
3. 阅读提取文字，用页码或搜索定位。选中同一页中的原句，点击“将所选原文放入阅读草稿”。原句单独展示，个人解释可以另行填写；此时尚未确认阅读。
4. 核对原句和位置，填写笔记，勾选阅读确认并保存。服务器核对文档归属、页码、精确字符范围、原句和文件/页文字哈希，生成阅读位置。
5. 主动点击“依据资料修订方向”，审阅模型提议后决定是否接受。保存笔记本身不会自动改写候选。
6. 候选判断中的“查看原文”可回到对应文件与页码，高亮原句；笔记下方列出引用它的候选、支持/限制关系和具体论断。笔记的“查看原文”同样可用。

已有环境请在 `webapp` 中重新运行 `Setup-Workbench.ps1`，安装新增的 `pypdf==6.21.2`，再重启服务加载新源码。当前项目虚拟环境已经安装该依赖。启动器会提示仍在运行的旧版本。

## 保存与传输

| 内容 | 保存与使用范围 |
|---|---|
| 原始文件 | 独立 SQLite BLOB 表；和项目中的文档记录在同一事务保存。按项目和文档 ID 下载，下载前核对字节哈希。 |
| 提取文字 | 保存页码、原文文字、页 SHA256 及整篇提取文字 SHA256。TXT/MD 视为一页，换行统一为 LF；原始文件字节保持不变。 |
| 精确摘录 | 保存文档 ID、页码、Unicode 字符起止位置、原句、文件与页 SHA256。起点从 0 计，右端不包含；中文和 emoji 均按 Unicode 字符定位。 |
| 阅读笔记 | 原句与个人解释分别保存，仍需人工确认。原有手写笔记和用户声明的版本/哈希三元组继续兼容。 |
| 候选证据 | 模型只能引用真实已确认笔记的 `note_id`；服务器复制定位到证据快照。不能由模型伪造或改写文件定位。 |
| 方向模型请求 | 仅在明确请求修订时发送既有简报、材料、题录等上下文，以及已确认笔记和选中原句；整篇导入正文与未确认草稿不随之发送。上下文超过 5 万字符时明确停止，不静默截断。 |
| 决策包与计划 | Markdown 保留原句、个人解释、文件名、页码、字符范围及哈希，不附整篇正文。完整项目 JSON 则包含已保存的分页文字。 |
| 工作空间备份 | 保留分页文字、笔记、证据及定位，不包含原始文件 BLOB。恢复后可继续查看文字和跳转摘录，明确标记文字快照与原件缺失。重新上传相同原件可补回原始字节，保持文档 ID 与已有定位。 |

上传、阅读、搜索和保存笔记不调用模型。原始文件与题录的对应关系由用户确认；字节完整性和精确定位不等于认证论文真实性，也不证明候选论断得到原句支持。

## 当前边界

单文件最多 8 MiB、120 页、40 万提取字符；每个研究最多 12 份文档、200 万提取字符。单条原句最多 4000 字符，不跨页。PDF 提取使用固定子进程，15 秒超时，配置解析/解压和输出上限；没有操作系统级硬内存沙箱。

扫描版、无文字层、加密 PDF 不支持；不会自动 OCR 或抓取订阅全文。当前阅读器展示提取文字，公式、分栏和排版可能有误，可下载保存的原件对照。某一页或文件发生变化时，不把失配的旧定位显示为精确引用。
