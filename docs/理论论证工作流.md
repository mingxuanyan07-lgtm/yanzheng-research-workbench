## 使用

在实验工作台切换数值实验/理论论证，不新增侧栏模块。选择已有研究项目，填写数学问题卡并保存；旧项目自动以空工作区兼容，无需改变已选课题。

问题卡字段为 `title`、`statement`、`domain`、`definitions[]`、`assumptions[]`、`target`。卡版本随实际编辑递增，旧版本归档；旧页面提交必须携带 `expected_version`，避免覆盖新卡。浏览器按项目保存未提交草稿，提交失败不丢弃。

保存命题卡，点击“检查下一轮材料”查看实际完整消息及纳入/排除原因；预览不请求模型。再点击“请千问提出修订”才会使用本机模型配置，向百炼发送卡、研究上下文及页面展示的最多十条有效确认笔记。一次操作一次请求，无自动重试；上下文超过50000字符则停止。问题卡保存、查看、导出和创建公开案例不调用模型。

模型只能输出 `revised_card`、`revision_reason`、`proof_routes`、`search_leads`。每条路线包含步骤、引理义务、同路线依赖、缺口及笔记关联；校验拒绝未知字段、无效引用、重复ID或依赖环。所有引理均未闭合，程序固定为 `not_formally_verified`。

提议不会立即更改问题卡。页面显示逐字段差异、理由与出处，用户可接受或拒绝；接受后保留旧卡，拒绝后保留当前卡。拒绝时可填写最多2000字的审阅备注，归档并导出；下次手动请求会携带最近两条适用的明确反馈，并标为未经验证，不能自动认定数学错误。新的提议替代旧待审提议时也归档。卡、证据或方向上下文已变化的提议不能接受。生成失败或超时保留当前卡、输入及既有提议，可手动重试。

## 失败原文与审阅

服务端在JSON/结构校验前捕获实际响应，新增 `failure_records` 独立于合法提议。记录原调用ID、提示、实际用量（未知为null）、原卡版本/哈希/快照、实际输入上下文与错误详情。原文最多50000字符，传输体上限256KiB，非JSON不强行包装，截断/缺失/脱敏明确标识。非法ID（含首尾空格）原样归档，不修正后宣称通过。浏览器不能上传原模型材料。

网页默认折叠失败详情，支持原文、具体反馈、单条及整体JSON/Markdown导出。反馈与结构/服务失败分别记录，所有意见均未经独立数学核验；失败材料没有接受入口。反馈带版本与幂等标识，重复提交不增记，冲突保留本机草稿。

三类反馈（普通被拒提议、旧rejected_outputs、新failure_records）统一校验生成时基础上下文。新记录的feedback_context保存项目ID、卡/版本、研究背景、有效笔记/来源、已有路线与案例出处快照及规范JSON SHA256；审阅自身不参与该指纹。旧失败记录的服务器v1基础指纹仍兼容；其他缺依据旧记录明确排除，保留原件，不在补写意见时伪造历史依据。缺原提交内容时不拿规范化提议冒充原文。

下一轮只取最近两条适用反馈，带完整原内容；卡版本或基础上下文变化、无意见、缺正文、截断或脱敏均明确排除，超过总预算则阻止生成而不截断出错步骤。预览token过期时返回409且不发请求。旧项目兼容，旧离线 `record_rejected_output` helper不暴露为上传API。保存意见、查看和刷新均不自动调用模型或重试。

## 证据与真实性

模型证据只能引用本项目有效笔记 `note_id`。快照保存检索轮次/来源ID、题名、版本、URL、阅读位置、完整笔记、确认时间、来源标签，以及笔记内容/笔记记录/题录记录的SHA256。上述哈希不等于已获取原文文件的指纹。

摘要笔记只可作为背景，正文笔记才可提出支持/限制关系。关系标为待语义审阅，结构通过不证明引用适用或数学正确。未有确认笔记时仍可形成待查证明思路，但不得生成虚构证据；检索线索不会自动记为已检索。

预置示例引用 [UW–Madison Math 521 Uniform Convergence](https://people.math.wisc.edu/~angenent/521.2017s/UniformConvergence.html) 的点态反例、定义和一致极限连续性定理（相关段落核对于2026-10-16）。创建时生成独立项目，`example_provenance.evidence_note_ids` 只授权这些预置材料；它们为 `curated_example`，不作为当前用户阅读声明。原材料记录为提供的资料，实时查询次数为零。示例提议也为预置，`model_call_id=null`，不会伪造模型调用、选题或Lean检查。

案例使用已知结果验收：原命题“连续函数列逐点收敛则极限连续”被 `x^n` 在 `[0,1]` 上的已知反例限制；预置提议加强为一致收敛，给出 ε/3 自然语言提纲与待审义务。不据此宣称发现新定理或完成形式证明。

## 实现和API

- `webapp/theory.py`：卡、提议、证据、依赖与版本校验，模型输入和Markdown。
- `webapp/theory_examples.py`：明确标记的公开可靠性示例，不联网。
- `webapp/app.py`：在写事务之外调用模型，项目操作锁与输入版本冲突保护；程序记录实际调用。
- `webapp/static/`：同工作台双路径、草稿恢复、差异、出处、路线与历史。
- `webapp/lean_api.py`：独立 Lean 预约、卡上下文、并发与去重、持久化及下载；不修改理论状态。
- `webapp/lean_service.py` / `lean_worker.py`：沿用已经验收的固定案例后端及信任审计，不接收任意模型生成证明。

| 接口 | 行为 |
|---|---|
| `GET /api/projects/{id}/theory` | 获取工作区及实际可发送的证据笔记范围 |
| `POST /api/projects/{id}/theory/card` | `{card,expected_version}` 保存卡 |
| `GET /api/projects/{id}/theory/next-context` | 预览完整messages、token、字符预算及三类feedback_dispositions纳入/排除原因，不调用模型 |

| `GET /api/projects/{id}/theory/failures/{failure_id}` | 读取本项目失败材料；同路径 `/export?format=json|md` 下载，默认JSON兼容 |
| `POST /api/projects/{id}/theory/failures/{failure_id}/reviews` | `{reason,expected_revision,request_id}` 保存具体意见；无原文上传字段 |
| `POST /api/projects/{id}/theory/proposals/{proposal_id}/accept` | `{}` 接受未过期提议 |

| `GET /api/lean/status` | `{"environment": ...}`，检查固定工具链与资源后端 |

| `GET /api/projects/{id}/lean/runs` | `{"runs": [...]}`，历史记录及当前上下文关联 |

| `GET /api/projects/{id}/lean/runs/{run_id}/export?format=json` | 下载单条完整 entry |

所有理论更新保留 `direction_map.selected_topic_id`，与原数值实验独立。SQLite使用新增可缺省字段，无需删除或重建已有数据库。原方向生成流程对预置案例笔记不会误记为用户确认阅读。

## 固定 Lean 核验边界

独立项目固定 Lean 4.33.1；只执行注册案例，不接受模型或用户提交的源码。无需 mathlib、证明模型或 GPU，不修改全局工具链。当前适配器 Windows Job 资源管理、输出限制、凭据清除与公理审计的细节见 [独立后端说明](../output/lean-validation/README.md)；它没有文件系统/网络隔离，不是通用代码安全沙箱。

当前 `-t1` 配置信任固定工具链的已编译导入，新本地声明仍由 Lean 内核检查；未运行独立 `leanchecker`，未逐次重验全部导入。固定源码锁、目标及传递公理/信任审计和 Windows Job 资源限制保持不变。

核验前，程序以短事务保存项目 ID、当前卡版本和规范 JSON 的 SHA256；实际计算在数据库写事务之外，随后追加独立 `lean_runs` entry。内层 `verification` 完整保留服务原记录；外层 `context` 保存卡快照，`association_status` 始终为 `context_only_not_semantically_verified`。列表、项目读取及导出按当前卡重新计算 `context_matches_current`：卡变化时为 `false`，无卡为 `null`。即便为 `true`，也只表示上下文相同，未确认数学语义对应。

固定案例 `passed` 仅针对记录中的准确形式陈述，须同时通过目标及传递公理/信任审计；退出码0不够，`sorryAx` 判 `incomplete`，未认可公理及额外信任依赖阻止通过。结果不会关闭自然语言引理义务、更改选题或把卡标为已证明。`error`、`incomplete`、`timeout`、`unavailable` 均不能推出命题为假。

结果持久化不改变卡、理论历史、项目 `updated_at` 或自然语言状态；普通项目 JSON 和单次下载均可保留记录。旧项目缺字段按空记录读取，无需重建库。10 秒内同项目、案例和卡上下文重复提交复用记录；本机忙碌返回409，不自动重试。90秒预约到期后的下一次明确请求才标记旧预约中断，不自动恢复执行。完整请求、entry、HTTP错误与中断合同见 [API说明](../output/integration-backend/api-contract.md)。所有 Lean 操作均不触发隐式模型调用。

后续仍需研究者确认自然语言卡、具体义务与准确 Lean 形式陈述的对应关系，并单独验收这种关联。当前固定案例运行不承担任意数学问题的自动形式化，也不证明自然语言提议正确。
