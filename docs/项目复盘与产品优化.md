# 研证项目复盘与产品优化

复盘日期：2026-10-16（Asia/Shanghai）；本文复盘对象为 **0.4.0 本地单人工作台**、两个 Skill 与运行必需的历史材料。当前v0.5已加入理论论证、精确笔记快照、待确认修订与审阅反馈，新增实现和独立验收见 [理论论证工作流](理论论证工作流.md)；下文0.4发现不自动代表新功能仍未实现。

研证已从展示型原型推进到可保存、可查询、可用 Skill 规则组织模型流程、可登记阅读并运行固定随机 SVD 的研究工作台。当前最需要补的是**新版完整闭环的真实验收、文献证据的实质支持检查和公平可复现的实验评测**，不应再把已经写入源码的阅读回流与实验执行列成尚未接入的功能。

## 产品定位与用户成果

首批用户是有一定数学、编程或 AI 兴趣、尚未确定具体问题的学生与研究初学者。优先覆盖普通电脑、小规模材料、可复现的第一轮验证，以随机低秩逼近作为深入案例。

用户的关键成果是一张可审阅、可修订的研究卡：问题是什么、已有工作说到哪里、哪些条件尚未确认、第一轮怎样验证，以及何时修订或停止。候选生成、资料查找和实验各自保留来路，研究者负责最终选择；程序状态通过不替代科研判断。

## 已完成的架构与产品能力

| 层次 | 当前实现 | 仍需区分的边界 |
|---|---|---|
| 项目与交互 | 简报、澄清、候选比较、选择理由、项目恢复与导出 | 本地单人使用，无账户和项目权限 |
| Skill 科研流程 | 真正加载两个 Skill 全文与 SHA，模型决定澄清或直接给候选；支持材料修订、失败重试、旧版归档；模型结果先保存待确认预览，显式接受后应用 | 同一个模型流程，不是独立多智能体核验；待确认预览不是科学正确性认证 |
| 文献工作台 | Crossref/arXiv 真实题录查询、日志、失败与逐轮导出 | 每轮最多 5 条；API 摘要存在不表示内容已读 |
| 阅读与关联 | 用户确认摘要/正文笔记、位置和时间；复合来源 ID；支持/限制关系受阅读条件约束 | 用户声明尚非独立原文核验；未把每条引用锁定到不可变论文版本和具体笔记 |
| 固定实验 | 已选低秩/SVD 方向可运行真实随机 SVD/精确基线，保存参数、哈希、逐次结果与 JSON/CSV | 固定实现、有限矩阵；不接收任意代码，不是通用学科实验平台 |
| 结果回流 | 模型可读取最近三轮有限实验摘要，再由用户决定新方向 | 摘要分析不等于独立计算复核，也不代表模型本次执行实验 |
| 历史案例与小研 | 五份白名单 JSON、既有文献与实验档案；小研预设提示 | 历史成果不计为本项目刚完成的研究，小研不调用模型 |

结构与接口详见 [技术架构](研证技术架构.md)。文献 Skill 的命令行还支持 OpenAlex、JSON/RIS 导入；这些渠道尚不是网页入口。原展示、旧 ZIP、截图和本机接入验收导出不随仓库分发。

## 0.4.0 带来的实质变化

创建项目现在有两条路径：本地演示不调用模型；Skill 模式先保存输入再请求一次千问，信息足够可直接进入候选比较，不必固定完成问卷。提交澄清答案或补充材料继续请求，失败保留待处理输入与原方向。

真实检索、用户确认的阅读笔记与已有实验摘要进入 `workflow.build_messages`。程序限制模型只能引用提供的来源；题录关联被收窄为书目线索，支持或限制必须有确认阅读和定位。来源 ID 编入运行与来源两部分，避免不同轮同名 `S001` 串源；原始检索等级不被阅读笔记覆盖。

实验由用户选题后显式发起，固定 Worker 在数据库写事务外实际计算。运行记录保存启动时选题快照，后续选题变化不改其归属。模型分析结果时读取独立记录，不改写其执行状态。返回比较会清除当前选择，旧事件保留，后续仍需用户重新选择。

这些变化说明现有轻量架构可以承载第一个研究闭环。下一步更应围绕证据是否成立、修订是否有价值、实验是否可比来评估，而不是先更换智能体框架。

## 当前缺口与对应证据

| 缺口 | 当前源码/验证事实 | 下一步处理 |
|---|---|---|
| 新流程缺完整真实验收 | 流程测试用模拟模型和检索；真实数值 Worker 测试已执行，旧版真实 Qwen 验收不覆盖新流程 | 用公开材料完成一次新版浏览器全链路，逐步保存调用、检索、阅读和实验事实 |
| 阅读确认的实质范围待核对 | `/reading-notes` 记录 `user_attested`；程序不直接读取并比对原文 | 固定论文版本、具体阅读位置与摘录，人工检查每条 claim 的支持范围 |
| 证据定位尚不够细 | note 有轮/源/位置，但候选关联以来源 ID 为主，多条笔记未逐条绑定判断 | 补 `note_id`、准确版本/内容指纹和逐项证据引用，保留冲突材料 |
| 修订审阅已独立成步 | `/advance` 保存待确认预览（输入/上下文哈希、旧地图快照、diff），显式 accept 后应用并归档旧地图，可 reject；旧 `/generate` 仍直接应用 | 预览仍是摘要级 diff，且需完整真实浏览器端到端验收 |
| 实验比较仍属局部观察 | 每类一个合成矩阵、基线先测、p/q 工作量不同，指标为 Frobenius 误差 | 多个独立数据种子、匹配预算、对称计时与外部参考复核 |
| 任务可靠性限于本机 | 同步子进程、20 秒超时、进程内锁，无持久化任务/取消/硬内存限额 | 先验证异常与重启行为，再决定是否引入后台任务体系 |
| 公网条件未建立 | 无账户、项目权限、配额与隔离 | 作为单独里程碑，在多用户试用前验收 |

## 既有案例带来的设计约束

以下沿用 [已有案例复盘记录](../output/project-review/cases.json)，不宣称本轮重新审阅全部上游源码或验证其科研效果。

| 案例 | 对研证的具体启发 |
|---|---|
| LangSim | 科学计算走固定专业工具接口，明确输入、单位与失败状态 |
| LLMs for Hypothesis Assessment / LK99 | 保留支持、限制和待核查材料的来路，不把启发式分数包装成科学真假概率 |
| FunSearch | 在生成与执行前明确问题、评价器、基线和停止条件 |
| STORM / Co-STORM | 查询、来源、阅读和写作分阶段保存，允许检查中间材料 |
| GPT Researcher | 文献服务和模型组织分离，保留状态、成本与失败 |

当前实现采用这些职责划分，不把外部原型当成本仓库隐含依赖，也不据此宣称已经实现自动科学家或独立审稿。

## 当前验证能说明什么

2026-10-16 隔离入口检查通过 **116 项（Web 64、Skill 52）**。统一命令为 `python scripts/run_tests.py --suite all`，测试在临时数据库下运行，不读取正式研究记录，不发真实模型或检索请求；固定数值 Worker 的小规模计算确有执行。结果覆盖状态推进、阅读确认、来源边界、保存导出、并发保护、固定参数拒绝、种子复现和数值不变量。

这些测试说明程序在约定条件下的行为，不说明引用语义正确、课题新颖或方法普遍更优。旧版真实千问调用与手机布局检查属于本机历史审计，新界面和新版 Skill 全流程仍需独立验收。

旧离线实验保存三个固定合成矩阵、27 组配置、540 次随机运行和 60 次精确基线。当前执行器默认则是 18 组配置、54 次随机运行和 9 次基线；数量随参数变化，不可混用。采样重复不是独立数据集，小矩阵耗时不能推出一般加速结论，Frobenius 观察不能代替谱范数理论。

## 下一步决策

优先里程碑定为 **v0.5：完整闭环与证据质量验收**。完成真实公开检索、实际阅读、含支持/限制关系的候选修订、人工选择、固定实验、结果回流和保存恢复；对每条结论核查出处和读取范围。把“接口能运行”和“研究判断可信”分别报告。

方向流程已补上修订预览和精确阅读笔记绑定；同预算、多数据实例的数值证据已单独积累，但尚未完成完整真实端到端验收与独立引用审阅。统一记录问题、材料、调用预算、人工时间、Token 用量、引文与定位正确率、修订质量和可复现结果；没有完成这些评测前，不发布科研提效比例、自动创新性结论或普遍性能优势。

公开多用户试用另验账户、项目权限、配额、任务隔离、监控和备份恢复。GitHub 上传提供代码和复现说明，不等于已部署公网网站。具体验收条件见 [ROADMAP](ROADMAP.md)。
